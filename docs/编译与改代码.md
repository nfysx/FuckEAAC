## 1. 在 Visual Studio 里怎么用（VS 2022 / 2026 / Insiders 都一样）

**Visual Studio 没有 Rust 项目系统**，所以：

- ❌ 不要「新建项目」「.sln」——Rust 用 `Cargo.toml` 当工程文件，没有 sln。
- ✅ 用 **文件 → 打开 → 文件夹**，选 `D:\DSH\Ccc\FuckEAAC-Tauri`。
- ✅ `.rs` 文件能编辑、能搜索、能比对，但**没有 Rust 智能提示/报错**（VS 不带 Rust 语言服务）。
  想要补全和实时报错，用 VS Code + `rust-analyzer` 插件（你机器上 `D:\NFY\Microsoft VS Code` 已有），
  或者就接受 VS 当"高级记事本 + 终端"。
- ✅ 编译/运行全部在 **VS 的集成终端**里做：**视图 → 终端**（View → Terminal），然后敲下面的命令。

### 终端里第一次要先做的事（只做一次）

```powershell
# 让终端找得到 cargo / rustc（VS 的终端默认 PATH 里没有）
$env:PATH = "$env:USERPROFILE\.cargo\bin;" + $env:PATH

# 前端依赖（只有 @tauri-apps/cli 一个）
cd D:\DSH\Ccc\FuckEAAC-Tauri
pnpm install
```

> 如果 VS 终端里 `cargo` 一直找不到，就把 `%USERPROFILE%\.cargo\bin` 加到系统 PATH，
> 或者用绝对路径调它：`& "$env:USERPROFILE\.cargo\bin\cargo.exe" build --release`。
> （仓库里没有放 .cmd 双击脚本 —— 那类脚本只对本机开发有意义，对下载代码的人没用。）

### 编译相关的全部命令

```powershell
cd D:\DSH\Ccc\FuckEAAC-Tauri

# —— 只编后端（最快，用来确认没写错）——
cd src-tauri
cargo check                 # 只检查不生成 exe，几秒钟
cargo build                 # 调试版 → target\debug\fuckeaac.exe
cargo build --release       # 发布版 → target\release\fuckeaac.exe（约 3.5 MB）
cargo test                  # 跑单元测试
cargo test -- --ignored --nocapture   # 端到端测试：造个假游戏进程跑完整条等待链
cargo fmt                   # 按标准风格格式化代码（改完代码建议跑一次）
cargo clippy --all-targets  # 静态检查（当前是 0 warning，别让它变多）

# —— 开发模式（改 Rust 自动重编，改前端按 F5 刷新）——
cd D:\DSH\Ccc\FuckEAAC-Tauri
pnpm tauri dev

# —— 打安装包（首次要联网下载 NSIS，约 2 MB）——
pnpm tauri build            # 产物：src-tauri\target\release\bundle\nsis\*.exe
```

### 想在 VS 里按 F5 直接跑？（可选，需要自己建两个小文件）

> 说明：原先工程里放了 `.vs\launch.vs.json` 和 `.vs\tasks.vs.json`，**已按需删除**（不是每个人都用 VS）。
> 想要的话照着下面自己建即可，VS 打开文件夹时会自动读取：

`.vs\launch.vs.json` —— 让工具栏的启动按钮能直接跑 exe：

```json
{
  "version": "0.2.1",
  "defaults": {},
  "configurations": [
    { "type": "default", "name": "FuckEAAC（debug）",   "project": "src-tauri\\target\\debug\\fuckeaac.exe",   "args": [] },
    { "type": "default", "name": "FuckEAAC（release）", "project": "src-tauri\\target\\release\\fuckeaac.exe", "args": [] }
  ]
}
```

`.vs\tasks.vs.json` —— 右键任意文件 → **任务**，就能跑这些命令（把 PATH 里加上 cargo）：

```json
{
  "version": "0.2.1",
  "tasks": [
    { "taskName": "cargo check（编译检查）", "appliesTo": "*", "type": "command", "command": "cmd.exe",
      "args": ["/c", "set \"PATH=%USERPROFILE%\\.cargo\\bin;%PATH%\" && cargo check --manifest-path \"${workspaceRoot}\\src-tauri\\Cargo.toml\""] },
    { "taskName": "cargo build --release（出 exe）", "appliesTo": "*", "type": "command", "command": "cmd.exe",
      "args": ["/c", "set \"PATH=%USERPROFILE%\\.cargo\\bin;%PATH%\" && cargo build --release --manifest-path \"${workspaceRoot}\\src-tauri\\Cargo.toml\""] },
    { "taskName": "cargo test（跑测试）", "appliesTo": "*", "type": "command", "command": "cmd.exe",
      "args": ["/c", "set \"PATH=%USERPROFILE%\\.cargo\\bin;%PATH%\" && cargo test --manifest-path \"${workspaceRoot}\\src-tauri\\Cargo.toml\""] },
    { "taskName": "pnpm tauri dev（开发模式）", "appliesTo": "*", "type": "command", "command": "cmd.exe",
      "args": ["/c", "set \"PATH=%USERPROFILE%\\.cargo\\bin;%PATH%\" && cd /d \"${workspaceRoot}\" && pnpm tauri dev"] }
  ]
}
```

> ⚠️ 这是 VS 的"文件夹项目"机制，格式随 VS 版本略有差异。
> 如果 VS 提示配置无效，直接删掉 `.vs` 文件夹即可 —— 终端里的命令是永远可用的那条路。

### 想看 Rust 的日志 / 打断点

- 调试版带 PDB 符号：**调试 → 附加到进程（Attach to Process）**，选 `fuckeaac.exe` 就能附加上去。
- 更实用的方式：程序日志写在 `%ProgramData%\FuckEAAC\fuckeaac.log`，界面上点「打开日志」，
  或者终端里 `Get-Content "$env:ProgramData\FuckEAAC\fuckeaac.log" -Wait` 实时看。

## 2. "我想改 X，该动哪个文件"

| 想改什么 | 改这里 | 备注 |
|---|---|---|
| 顶栏文字、按钮名字、界面排版 | `src\index.html` | 纯 HTML，改完按 F5 |
| 颜色、间距、深色/浅色主题 | `src\styles.css` | 颜色变量都在文件开头 `--xxx` |
| 界面的行为（点按钮干什么、提示文案） | `src\main.js` | 每个动作一个 `doXxx()` 函数；`bind()` 里是按钮绑定 |
| 进游戏时要停哪些软件 | `src-tauri\src\config.rs` 的 `default_config()` | 或直接改 `FuckEAAC.config.json`（推荐，不用重编） |
| "停用/恢复"到底执行什么命令 | `src-tauri\src\actions.rs` | 全工程只有这个文件会改系统 |
| 等待游戏进程的逻辑、超时时间 | `src-tauri\src\play.rs` | 文件开头有 `APPEAR_MINUTES` 等常量 |
| 检测哪些服务/驱动/进程 | `src-tauri\src\detect.rs` | 只读检测 |
| 环境诊断那几项检查 | `src-tauri\src\diag.rs` | Secure Boot / TPM / 测试模式等 |
| 托盘菜单、关窗行为、窗口大小 | `src-tauri\src\main.rs` | 窗口几何在 `tauri.conf.json` 也有默认值 |
| 程序名、版本号、窗口默认尺寸 | `src-tauri\tauri.conf.json` + `package.json` + `Cargo.toml` | 三处版本号要一起改 |

改完 Rust 代码后的固定动作：

```powershell
cd src-tauri
cargo fmt && cargo clippy --all-targets && cargo test
```

## 3. 常见问题

**Q：`cargo build` 报"failed to remove file ... 拒绝访问"？**
A：exe 还在运行（或被托盘里的实例占着）。先彻底退出程序，或
`Get-Process fuckeaac -ErrorAction SilentlyContinue | Stop-Process -Force`，再编。

**Q：VS 里找不到 `cargo`？**
A：VS 的终端不继承你的用户 PATH。跑一次 `$env:PATH = "$env:USERPROFILE\.cargo\bin;" + $env:PATH`，
或者用工程根目录的 cmd 脚本。

**Q：`pnpm tauri build` 卡在下载 NSIS？**
A：打包安装包需要联网下载 NSIS 工具链（首次约 2 MB）。没网就先只用
`cargo build --release`，直接拿 `target\release\fuckeaac.exe` 用（免安装，双击即跑）。

**Q：改了前端没变化？**
A：在窗口里按 **F5** 刷新（WebView2 会重新加载 `src\` 里的文件）。
`pnpm tauri dev` 时改 Rust 会自动重编，改 HTML/CSS/JS 不用重编、刷新即可。

**Q：编译报错看不懂？**
A：先 `cargo check --message-format short` 拿到简短的错误行号，再 `cargo check` 看完整解释。
Rust 的报错一般会直接告诉你该改成什么。
